# 网页后端更新

从 Remote 0.2.6 起，**设置 → 检查 Remote 更新** 可以检查当前连接的
Windows x64 或 Apple Silicon 后端。当前版本从后端安装读取，而非侧栏的网页版本。
发现最新正式版后，只显示版本号和 **更新至…** 按钮，不展示摘要。
点击按钮才开始安装。检查已是最新版时，页面、草稿及 Service Worker 保持不变。

## 安装与进度

后端必须通过此安装所属的 `CodexRemote` 计划任务或 `com.codex.remote`
LaunchAgent 运行。手动启动、服务目录冲突和不支持的系统只允许检查，不允许远程安装。
旧后端需要先在本机升级一次到支持此入口的版本。

网页入口复用 `desktop/updater.mjs` 的安装协议，标准安装优先使用校验后的预构建运行包，
源码定制使用隔离构建。保留本地文档、规则和私有运行数据，源码冲突仍阻止覆盖。
下载、解压、环境检查、备份均在停服前进行。安装过程只重启所属 Remote 后端，
保留 Codex Desktop、已有隧道及独立代理。管理器程序及其版本不参与此更新。

独立任务在 `output/web-update/<任务标识>/` 保存更新器及其运行依赖快照：
Windows 通过 WMI 启动独立进程，macOS 通过单独的 launchd 作业运行，
避免被 Remote 系统服务的停止操作一起结束。任务记录包含本地诊断和恢复证据，
不应公开。网页只读取版本、阶段、百分比、时间和经过投影的状态。

下载百分比根据已接收字节计算，其余百分比反映已完成的阶段。
后端短暂退出时，网页保留最后确认的百分比并等待重连，不编造离线进度。
关闭弹窗不会取消任务；重新打开、网络恢复或刷新网页后，可继续读取持久进度。
启动请求响应丢失后只读取任务记录，绝不自动重复提交安装。

## 网页刷新

安装成功并完成后端健康检查后，浏览器从 `/remote-client/` 获取该后端配套的
公共前端，校验网页版本，安装完整公共缓存，再激活并刷新。
这些路径仅发布 `dist/client` 的公共文件，不发布配置、认证或聊天数据。
它们绕过项目原有的边缘静态路由，因此无需给远程更新任务 Cloudflare 凭据。
部署者的反向代理也必须将 `/remote-client/*` 转发至 Remote；
若把它改成静态快照，自动刷新会报版本不一致，后端更新不会因此回滚。
原有静态边缘部署不会被此操作改写。

刷新后的窗口继续使用后端公共资源路径；其他已打开的窗口保留原有公共缓存。
没有 Service Worker 的 HTTP 浏览器会打开后端公共页面路径。
网页刷新失败可以单独重试，无需重新安装后端。主会话文字草稿、认证和通知订阅保留；
待发图片、技能选择、临时侧聊及 Remote 自有终端会在页面刷新或后端重启时丢失。
进行重要交互或使用这些临时内容时，应先完成再更新。

## 失败与恢复

准备失败不停止原后端。替换或启动失败会使用原有事务日志恢复旧文件、依赖和运行状态，
网页明确显示失败或已恢复旧版，不将其作为更新成功刷新。
检测到未完成安装时，**恢复旧版** 使用本地证据，不要求再次下载版本。
恢复不会覆盖中断后再次被修改的源码。

若断电、独立任务被结束或文件损坏导致后端完全不能启动，网页无法控制一台不可达的主机，
需要在本机管理器恢复。保留 `output/manager-update`、`manager-backup-*`
及 `web-update` 的现场后再排查，不要手工删除更新锁或备份。
macOS 登录、系统退出与真实已登录 Desktop 的远程升级仍需现场验收；
CI 和合成后端不能替代该结论。

## 权限

更新路由要求有效登录、可信 Origin 和 JSON 请求；安装还要求短期有效的检查令牌、
匹配版本和幂等任务标识。客户端不能传入安装目录、下载地址、命令或任意版本。
只能安装官方仓库的最新稳定版，不能降级。更新器遵循主机显式配置的
`HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`，不会修改全局代理或软件源。
密码及设备管理仍只通过本机管理器的 IPC/stdin 提供。

## 验证

聚焦测试覆盖检查权限、参数过滤、最新版本重核、重复提交、更新器快照依赖、
启动失败、持久进度、脱敏投影及后端专属控制。原有更新器测试继续验证
冲突检查、运行包校验、备份、安装失败回滚及中断恢复。
浏览器验收使用合成会话与更新状态，检查手机、桌面、断线、进度、关闭后继续读取和刷新流程。
本批本地完整测试为 602 项、87 个文件通过；8 组视口通过当前版本不刷新、更新进度、
关闭弹窗继续监测、离线进度保留、完成后网页切换与公共缓存隐私检查。
Windows WMI 独立任务在两个临时安装中完成实际运行文件和依赖替换、新后端启动，
以及注入健康检查失败后的旧版回滚；认证哨兵文件保持不变。
这些验收使用合成后端，未触碰真实聊天或用户认证。
