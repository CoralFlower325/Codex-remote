# Codex 运行时错误

从 0.1.16 起，Remote 直接消费当前 Desktop 的原生 `error` 通知及轮次 `error` 字段，
主会话、临时侧聊和子智能体使用相同的轮次显示。提示保留在执行过程折叠之外，
没有助手回复的失败轮次也能显示。重新打开会话时，有界原生轮次读取保留最终错误。

0.2.5 对照本机 Desktop 26.1027.3384 的错误组件，采用灰色图标与紧凑文字行，
取消 Remote 自行添加的彩色卡片、中文类型标题及重复 HTTP 标签。
最终错误按原生规则提取 JSON 错误中的 `error.message`，普通错误保留原文；
文字中的真实状态码不会被改写或补造。公开错误元信息仍保留在轮次模型中，
不会为了外观丢弃。附加说明可点击错误行旁的箭头展开，长文本自动换行。

原生 `willRetry: true` 使用流错误样式，不会提前结束轮次。
只有原文包含原生 `Reconnecting n/m` 格式时才显示中文重连进度，
不使用浏览器重试次数冒充模型重试次数。原生服务繁忙或对应的 429 流中断，
沿用 Desktop 的“服务器繁忙，正在重新连接”格式。
收到同轮次实际输出恢复或原生轮次完成后，暂时性提示清除；
后台未完成快照不能覆盖仍有效的重试状态。最终失败依照原生轮次结果保留。
临时侧聊的重连快照仅存于宿主内存；瞬时重试通知未被原生历史持久化时，
完整页面重开不保证能恢复该瞬时状态。

请求级 RPC 错误同时保留数值错误码和投影后的公开错误信息，不传递任意原始结果。
RPC 错误码与 HTTP 状态码分开显示。Remote 不替 Codex 发送新的模型重试请求，
也不自动更换模型、账号或代理。管理器公网探测失败与模型服务错误分别处理。
网页顶端的传输重连独立使用黑白 `Reconnecting` 提示，按需显示 `Retry`；
点击仅恢复 Remote 连接，连接恢复后隐藏，不重发模型动作。

实现与安装版本生成的协议 `ErrorNotification`、`TurnError`、`CodexErrorInfo` 对照。
验证使用合成事件及隔离桥接，不故意触发真实账号限流或额度消耗。
桌面、402px 手机竖屏、874px 横屏和 320px 窄屏均检查了原文、重试恢复及长文本布局。
0.2.5 的合成重连与错误检查包含在 `scripts/check-composer-layout.mjs`，
截图和结果写入忽略目录。账号套餐、用量重置时间、云环境重试及原生诊断导航
依赖 Desktop 自身账户上下文，Remote 保留收到的错误内容，不推测这些账户状态。
