# Codex 运行时错误

从 0.1.16 起，Remote 直接消费当前 Desktop 的原生 `error` 通知及轮次 `error` 字段，
主会话、临时侧聊和子智能体使用相同的轮次显示。提示保留在执行过程折叠之外，
没有助手回复的失败轮次也能显示。重新打开会话时，有界原生轮次读取保留最终错误。

界面保留错误原文，以中文标注已有的错误类型，例如请求频率受限、额度耗尽、
上下文上限、服务繁忙及响应中断。只有原生结构携带 `httpStatusCode` 时才显示
HTTP 状态码，不把所有限流或额度错误推断成 429。未知类型显示通用标题，
“错误详情”保留原生类型名称与公开附加说明，长文本有界并自动换行。

原生 `willRetry: true` 显示“Codex 正在重试”，不会提前结束轮次。
收到同轮次实际输出恢复或原生轮次完成后，暂时性提示清除；
后台未完成快照不能覆盖仍有效的重试状态。最终失败依照原生轮次结果保留。
临时侧聊的重连快照仅存于宿主内存；瞬时重试通知未被原生历史持久化时，
完整页面重开不保证能恢复该瞬时状态。

请求级 RPC 错误同时保留数值错误码和投影后的公开错误信息，不传递任意原始结果。
RPC 错误码与 HTTP 状态码分开显示。Remote 不替 Codex 发送新的模型重试请求，
也不自动更换模型、账号或代理。管理器公网探测失败与模型服务错误分别处理。

实现与安装版本生成的协议 `ErrorNotification`、`TurnError`、`CodexErrorInfo` 对照。
验证使用合成事件及隔离桥接，不故意触发真实账号限流或额度消耗。
桌面、402px 手机竖屏、874px 横屏和 320px 窄屏均检查了原文、重试恢复及长文本布局。
