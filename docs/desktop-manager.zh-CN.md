# 本机管理器

可选的小型桌面工具，用来控制已经配置、构建好的 Codex Remote，
独立于网页服务运行。它保留 Codex Desktop，不创建模型任务，不提供网络启停接口。

## 安装与打开

从对应 [GitHub Release](https://github.com/CoralFlower325/Codex-remote/releases)
下载 Windows 安装程序或 macOS DMG/ZIP。
Windows 提供 x64，macOS 仅提供 Apple Silicon（arm64）。首批安装包未签名，
可能需要按 Windows 下载信誉或 Gatekeeper 流程确认。
签名、公证和 macOS GUI 实机验收待完成。

源码启动：

```bash
npm ci
npm run manager:install
npm run manager
```

优先恢复已保存且有效的安装目录；首次打开或记录失效时，自动检查 Windows 的 `CodexRemote` 任务、
macOS 的 `com.codex.remote` LaunchAgent、程序附近和用户常见目录。
唯一已注册服务优先；多个未注册安装显示下拉候选，不自动猜选。扫描按钮可再次探测，也可手动浏览目录。
选择包含已配置 `.env`、`package.json`、`scripts/` 和 `dist-server/` 的目录；
缺少文件时先完成主机安装。探测只读取元数据，不启停服务。
系统任务或 LaunchAgent 属于另一目录时禁用控制，不覆盖其他安装。
旧版平台脚本缺少 JSON 状态输出时，管理器使用随包提供的只读检测脚本，
无需先手工修改旧脚本。

## 日常使用

- 复用平台脚本开启、关闭、重启 Remote，保留 Codex Desktop。
- Windows 服务和隧道通过无窗口任务运行，无需常驻终端。首次开启自动迁移旧任务；
  后端输出写入 `data/server.out.log`、`data/server.err.log`。
  `npm start` 仍是开发时使用的前台命令。
- 最小化或关闭窗口后，Windows 常驻右下通知区域，macOS 常驻**顶部菜单栏**；
  从图标重新打开窗口。macOS Dock 是另一个位置。
- Remote 关闭或状态未知时，驻留图标为半透明灰色；受管服务运行时使用实色，
  深色系统区域显示白色，浅色区域显示深色。Desktop 或公网入口异常不等同于服务停止。
- 托盘菜单提供状态、显示窗口、打开 Remote、启停、检查更新和退出。
  退出管理器保持 Remote 当前状态。
- macOS 的 Dock 切换结束后，通过 Finder、Spotlight 或 Dock 再次打开会恢复隐藏窗口。
  操作错误保留至手动清除或发起下一次操作，记录中保留有限长度的原因。
  正常健康轮询不会抹除操作错误或禁用恢复控制；检测错误独立显示，恢复后自动清除。
- 安装版可设置登录启动管理器，与 Remote 服务的登录启动相互独立。
  开启/关闭仍会启用/禁用 Remote 自己的登录启动。
- 每五秒检测一次，不重叠请求；区分后端归属、Desktop 同步、访问密码及受管理的 Windows 隧道。
  进程存在不等于健康，超过二十秒的读数显示过期。
- Desktop 诊断区分调试端点未就绪、缺少 Desktop 页面和原生桥接待连接。
  普通启动 Codex 不保证开启 9229，需使用安装指南中的调试启动参数；
  Codex++ 等启动器也可能代为传入参数。Remote 使用 Desktop 的端点，
  不连接启动器自己的本地服务。连接恢复后自动清除诊断。
  开启 Remote 可以成功但桌面同步仍待就绪；Desktop 连接前整体仍显示“需要检查”。
- macOS 的独立 LaunchAgent/daemon 隧道仍由外部管理，管理器不会接管或停止它。
  “隧道管理”区分受管任务、外部管理与未配置受管隧道；
  “公网入口”单独检查已配置地址的 `/health`，不携带 Cookie、不跟随重定向。
  公网可达不代表已确认隧道归属或具体链路；检测失败也不会停止健康的本地服务。
- 操作记录数量受限，只保留内存中的管理器操作。文件仅在本机打开，不上传诊断。

## 诊断和设备认证

0.1.15 将界面分为“概览”“设备与密码”“版本更新”。公网请求超时或网络失败显示“待确认”，
HTTP 错误及非预期健康响应显示“响应异常”。“复检连接”通过系统网络栈延长探测时间；
也可打开入口、查看限量脱敏的本地日志。确认修复后只重启当前安装的 Remote 服务或
Windows 受管隧道，不重启 Desktop，不接管 macOS 外部隧道。
修复按钮不能代替 DNS、代理配置或 Desktop 调试端点的开启。

“设备与密码”通过本机 IPC 和标准输入管理认证，修改操作需要原生确认。
可修改访问密码、撤销一个或全部浏览器登录；修改密码会使所有旧登录失效。
已连接的网页及终端在下次活动时立即检查，空闲连接最迟五秒检查一次；
已经提交的模型工作继续执行。设备记录只保存浏览器/系统标签与时间，不保存 Cookie、
完整用户代理或 IP。同一设备的不同浏览器配置及每次登录各算一条会话。
列表最多显示最近 200 条有效记录；旧登录首次使用时才进入列表，“撤销全部”也能使
尚未出现的旧登录失效。系统推送权限需在设备上另行管理。
需要分别安装新版管理器和更新本机 Remote 才能使用这些功能。

## 本机更新

进入“版本更新”，检查新版并阅读摘要，再通过原生对话框确认安装。
已是最新版时不重启服务、不刷新窗口。系统 PATH 需要能找到
Node.js 22.19+，包含标准 Homebrew 路径。
定制源码更新还需要 npm 和 Git；预构建运行包更新不需要它们。

更新显示中文步骤、按已完成步骤计算的百分比、总耗时、当前步骤耗时和有数量限制的最近命令输出。
整体百分比按阶段分配；运行包下载阶段按实际字节推进，其他长步骤保持当前数值，
不估计剩余时间。超过三十秒没有输出会明确提示仍在等待。
依赖和测试工具的原始输出保留原语言，网络错误另有中文解释。
依赖请求有限重试，临时网络错误最多额外重试整条命令一次，保留现有依赖源和代理配置。
每条依赖安装、检查或构建命令最长等待十分钟，获取源码最长等待三分钟。
Release 检查与运行包下载使用管理器的系统网络栈，遵循系统代理；不修改系统或 npm 代理设置。

0. 0.1.14 起，标准安装优先下载当前系统的运行包清单。校验 GitHub 提供的 SHA-256，
   使用清单中的已安装版本基线检查本机源码；发现定制或缺少基线时走下述源码构建流程。
   标准路径下载平台运行包，核对归档摘要，拒绝越界路径、链接、重复文件和大小不符，
   校验每个文件后检查运行依赖及原生终端。不需要 Git、npm 安装或本机测试／构建，
   仍需 Node.js 22.19+。运行包与清单缺一时停止，不把发布未完成当成正常源码回退。
1. 源码路径在独立临时目录获取官方版本标签。
2. 将新版要修改的文件与已安装版本原始文件比较。允许 CRLF 差异，保留无关修改；
   根目录 `AGENTS.md`、`CLAUDE.md`、`README*.md` 以及 `docs/` 下 Markdown 的冲突保留本机版本，
   包括本机主动删除的文档。代码、配置冲突、本地源码删除、符号链接及受保护路径仍阻止安装。
   自定义 package/lockfile 可能需要维护者协助。
3. 在临时目录合并新改动和保留的本机 `src/`、`public/`、`scripts/` 及标准构建配置，
   再安装依赖、类型检查、测试和构建，旧服务继续运行。
   不复制运行时 `.env` 或私有数据；停服前在临时目录实际执行一次离线依赖安装，
   确认本次缓存可用；安装前再次检查构建输入的哈希。
4. 将受影响源码及构建备份到 `output/manager-backup-*`，关闭 Remote 并等待旧后端退出。
   保留文档的本机副本放在 `source/`，新版副本放在 `incoming/`；
   `receipt.json` 记录保留和删除状态。完成提示列出保留路径，供手工对照，不通过覆盖本机规则解决冲突。
5. 将原有依赖目录保留在备份中，再安装源码、构建及锁定依赖；
   标准路径复制已校验的运行依赖，源码路径使用已验证的缓存离线安装。
   此前运行的服务重新开启并检查健康，此前明确关闭的服务继续关闭。
6. 安装或启动失败时恢复备份，有原依赖目录时直接恢复，无需网络；原安装缺少依赖时才重新安装旧锁文件。
   恢复过程单独显示百分比和结果，不将恢复旧版显示成更新成功。
   恢复失败显示备份位置，需要人工处理；成功安装后的临时文件清理失败仅作为警告。

停止服务前持久保存 `output/manager-update/active.json`，在依赖搬移、文件安装、
服务验证和完成之间记录阶段。重开管理器或选择该安装目录时，先处理未完成事务；
恢复失败会阻止继续启停／更新，并提供“重试恢复”。恢复保留原依赖备份，允许恢复过程再次中断后重试，
此前关闭的服务不会自动开启。中断后又被人工修改的源码、损坏或缺失的备份会阻止自动覆盖，
保留现场供手工处理。已完成提交的事务不会回滚；准备阶段被终止时旧安装保持原状。
本机目录需要支持原子重命名与硬链接。

源码路径的准备构建、正式安装依赖和回滚共用本次更新专用的临时 npm 缓存，子 npm 命令也使用相同缓存；
不使用或修改原有用户缓存，结束后删除专用缓存。
若 macOS 在 `~/.npm/_cacache` 报 `EACCES`/`EEXIST`，
请先安装 0.1.12 或更新版本的管理器，再选择原安装目录重试主机更新。
更新前已正常连接的 Desktop 必须恢复；如果安装前桌面就未连接，
不会仅因此回滚成功的安装，诊断提示会继续显示。

保留 `.env`、`data/`、认证、附件和通知状态，不重置 Git、不推送安装目录。
更新文件保留为本地改动，后续按已安装版本标签比较，不假定 Git HEAD 干净或等于部署版本。
备份不会自动删除，保留旧前端分块供尚未关闭的网页继续使用。

这里更新**所选本机安装**。下方独立的管理器更新区更新管理器程序。
“本机管理器”和“Remote”显示各自的版本，可以不同；各自检查对应组件的已安装版本。
管理器从 0.2.0 起独立计版，Remote 更新不改变管理器及其版本号。每份 Release
分别列出两者的版本与修改内容；管理器无变更时不重新打包，沿用此前的安装包。
独立静态边缘/CDN 资源与外部隧道不由本机更新器部署。
配置公网入口的安装收到提示；外部静态托管仍需按托管指南同步前端资源。
如果 0.1.10 管理器被 Markdown 冲突阻止，请先安装 0.1.11 或更新版本的管理器，
选择原安装目录后重试。旧管理器仅检查主机新版无法获得已修复的更新器，
无需重置 Git 或删除本机文档。

## 管理器自更新

管理器 0.2.1 检查独立的 `manager-vX.Y.Z` 发布通道。Remote 沿用 `vX.Y.Z`，
管理器发布不能设为 GitHub 的最新版。已经是最新版时不会下载、安装或刷新窗口。
旧管理器首次需要手动安装一次支持自更新的新版。

在“版本更新”中点击“检查管理器”，阅读摘要后下载。进度按实际接收字节计算，
显示总大小和速度；取消下载会保留 Remote 运行。更新清单和平台安装包均校验
GitHub 提供的 SHA-256 摘要。仅支持 Windows x64 与 Apple Silicon，使用完整安装包。
下载中断后可以重试，但不保证按字节断点续传。

点击“安装并重新打开”后，需要原生弹窗确认。交接前复制并逐文件校验现有管理器程序，
备份设置，持久化安装记录，并再次核对安装包摘要。Windows 使用 NSIS 安装器，
不调用 Remote、Desktop 或隧道的启停操作。普通退出不会安装已下载的更新。
重启后只有管理器实际版本与目标一致才显示完成；失败或未确认时保留记录与备份。

当前 Mac 发布包尚未具备 Developer ID 签名和公证，可以检查版本并打开安装包下载，
会阻止自动安装。签名后的 Mac 更新逻辑仍需真实签名包升级验收，代码和构建 CI 不能代替。

备份位于管理器用户数据目录的 `manager-update-backups/<id>`，
`manager-self-update.json` 记录安装交接。更新页可打开备份目录，不自动清理备份。
**尚未实现管理器程序的自动回滚**：关闭管理器后重新安装上一版官方安装包；
保留设置及校验后的备份供手工恢复，不替换运行中的文件，不删除恢复证据。
安装记录损坏时会阻止安装，应先检查内容和文件权限。
详见[实现断点与恢复方法](manager-self-update-checkpoints.md)。

跨平台测试覆盖归属、版本判断、冲突、受保护路径、备份、恢复和关闭状态保持。
macOS 打包、shell 与 LaunchAgent CI 不能代替已登录 Mac 的菜单栏、Dock、
登录启动及 Desktop 集成验收。
打包工作流还会在 Windows/macOS 打开真实 Electron 窗口，使用合成健康数据检查布局、
隔离、最新版检查、最小化/关闭常驻，以及 macOS Dock 隐藏和恢复。
这项验证不连接已登录的 Desktop，也不修改登录启动项。
