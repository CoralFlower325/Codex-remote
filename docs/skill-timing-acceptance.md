# 技能消息与同轮计时验收

日期：2026-11-01。范围：Remote 0.2.7，稳定管理器 0.2.0 无变更。

## 修复范围

技能同时提交原生 `[$name](path)` 文本引用和 `skill` 输入。此前只有后者时，
模型可以收到技能，但两端没有可显示的用户文本。发送、引导、队列、侧聊共用输入
构造；队列编辑和停止后编辑保留技能，避免重复引用。历史显示可以投影旧纯技能
输入，原始记录保持不变。普通用户文字继续按纯文本显示。

计时条属于原生轮次的第一段回复，使用该轮最初的 `startedAt`，同轮引导不移动、
不重置。最终答案的 `startedAtMs` 跨分段传递给计时条，流式生成和完成后的用时
保持一致。整轮过程共用一个折叠入口，引导消息、最终回复、子智能体和错误仍可见。
读取半轮历史后补入更早分段时，计时归属前移，保留已有分段身份和展开状态。

## 复现验证

```bash
npm run typecheck
npm test
npm run build
node scripts/check-skill-timing.mjs
```

浏览器脚本通过独立合成后端运行实际生产前端，覆盖
`scripts/acceptance-viewports.json` 的八种桌面、平板和手机尺寸：

- 只选择一个技能，不输入文字，实际点击发送，核对原生文本和技能参数。
- 纯技能进入队列，编辑空文字并保存，再引导同一轮，技能不丢失、不重复。
- 引导前后只有一处计时，仍属于第一段回复，继续使用原生最初开始时间。
- 最终答案开始生成后冻结用时，完成和重开历史后保持同一数值。
- 同一个入口展开引导前后的过程，最终回复与用户消息没有重复。
- 所有尺寸检查横向溢出和浏览器错误，保留合成截图与本地结果。

单元测试另覆盖多技能、同名不同路径、图片混合、侧聊输入复原、停止后编辑、
历史补页、不同原生轮次和缺失时间数据。测试不向真实 Desktop 提交模型请求。
真实手机网络、输入法和已登录 macOS Desktop 的交互验收仍需单独完成。
