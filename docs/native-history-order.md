# 原生聊天顺序与晚到事件

Remote 展示原生轮次、条目、时间锚点和分页结果，不生成或改写聊天记录。
同一轮次内的完整条目顺序以原生列表或嵌入数组为准；实时单条通知只能更新其所属轮次，
不能因为网络到达较晚而追加到其他轮次之后。

0.2.3 修复旧轮次命令、消息和流式增量直接追加到最新回复之后的问题。
该条目继承旧轮次的原生总耗时，因而会在新回复后显示一段看似无来源的“用时”；
问题在条目归属和展示位置，不是凭空生成了这段原生时长。

- 已加载的旧轮次收到新条目时，在其轮次内更新，保留新轮次的位置。
- 未加载的旧轮次不凭实时通知扩展历史窗口；只用已知原生轮次时间判断窗口边界。
  没有可信时间时不猜测轮次先后；正常上翻仍通过原生分页读取完整记录。
- 晚到的旧轮次完成通知不清除新轮次的 activeTurnId；不改变任何原生时间值。
- 不用浏览器连接时间、相邻消息时间或空闲间隔估算用时；最终回复开始时间仍是优先冻结锚点。
- 主会话、临时侧聊及子会话共享条目更新约束，保留现有历史窗口、阅读锚点和原生问题。

回归覆盖状态更新、整轮嵌入条目、流式增量、窗口边界、当前轮次保留和最终渲染位置。
合成数据界面检查与真实聊天只读核对分开记录，不为验收发送模型请求或修改原生历史。

0.2.4 补齐随后的原生历史读取校准：原生数组决定共同条目的相对顺序，
只在实时流中出现的条目保留其原生邻接位置，读取期间的新文本优先保留。
校准不会因为实时到达顺序与原生顺序不同而重复条目，重复校准保持一致。

2026-10-31 本地验证通过 576 项测试、82 个文件，以及类型检查和构建。
八组规定视口重放晚到条目、增量、原生整轮数组及首次携带时间的窗口外完成通知，
检查消息顺序、原生用时、重新打开会话的一致性和横向溢出；未执行模型动作。
这不替代真实 iPhone 网络或已登录 macOS 的实机验收。
