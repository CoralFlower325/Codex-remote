# 原生待发与引导条验收

日期：2026-11-09。功能版本：Remote **0.2.27**，管理器 **0.2.6**。

## 交互契约

- 主输入始终只有一个主操作：运行中空输入显示停止，有文字、附件或技能时显示发送。
- 运行中点击发送先调用原生 `thread/queue/add`，不直接调用 `turn/steer`。
- 待发消息在 RPC 完成前立即显示在输入框上方；原生队列返回相同
  `clientUserMessageId` 后替换本地行，不产生重复或闪动。
- 待发条提供原生“引导”、删除和更多菜单；菜单包含编辑、在侧边聊天中打开和关闭排队。
- 点击“引导”使用原生 `turn/steer` 和当前 `expectedTurnId`，成功后再删除待发项。
- 关闭排队只影响当前活动轮次，后续发送直接引导；活动轮次结束后恢复默认排队。
- 会话历史入口紧靠主发送按钮左侧，不再夹在模型控件旁。

## 后续修复记录（2026-11-10，分支 fix/ux-findings-1-5）

针对 0.2.27 使用体验复审的发现 1–5，本分支在上述契约之上补齐：

- 普通发送（`turn/start`）与待发条“引导”均改走乐观呈现：点击后立即在
  会话时间线显示本地用户消息（发送显示“正在发送…”，引导显示
  “正在引导当前任务…”），原生条目到达后按 `clientUserMessageId` 去重；
  引导复用待发项自身的标识，`turn/steer` 被拒时撤下本地消息且待发项保留。
- 轮次状态单向推进：本地已知终结（完成/中断/失败）的轮次不会被滞后的
  计时快照改回运行中，快照也不能把已终结轮次重新标为活动轮次；
  将重试的错误轮次仍可按既有规则恢复为运行中。
- HTTP 失败兜底文案改为中文（`请求失败（HTTP …）`、连接超时中文提示）；
  自动任务页首次加载失败时只显示专用空状态，不再与原始错误并排重复。
- 待处理区优先级：审批条移到提问条之前；有待审批时待发条收起为一行
  摘要（可展开），待发超过 4 条时同样折叠，避免小屏上挤压会话流。
- 经有状态合成后端复测确认无需改动的两点：不满屏会话打开即预取一页
  更早历史（手势后即时呈现，符合“只预取、手势才消费”的契约）；快照
  如实反映中断时，输入区在完成事件后立即恢复空闲并显示“你在这…后
  停止了”。

验证：`npm test` 1055 通过（新增 5 项）、7 项失败为基线既有的真实 PTY
环境限制（与改动前一致）；`npm run typecheck`、`npm run build` 通过；
`check:browser` 八视口通过。真实 iPhone 与已登录 macOS 仍需单独验收。
