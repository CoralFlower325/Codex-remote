# 执行记录分组与展开验收

日期：2026-11-01。范围：Remote 0.2.11；稳定管理器 0.2.1 无变更。

## 故障复现

执行记录原先会为旧组中的每个条目记住同一个 React key。原生快照后来插入
进度消息，将一个连续组拆成几个组时，新组可能同时复用这个 key。继续合并、
拆分和重排后，React 可遗留没有有效事件处理器的旧 DOM，表现为重复的灰色
“运行了命令”行，其中某些行带箭头却无法展开。

使用旧模型源码 `6717b15`、当前实际 `ActivityGroup` 组件和合成命令，在本机
Chrome 的 1280 × 900 与 402 × 874 CSS 视口中均重现：

| 检查 | 修复前结果 |
| --- | --- |
| 反复插入进度、合组和重排后 | 模型预期 3 组，DOM 实际保留 4 组 |
| React 重复 key 警告 | 每个视口 10 条 |
| 依次点击四个残留入口 | 其中一个 `aria-expanded` 仍为 `false` |

无正文、无提问的助手占位消息也会拆开执行组，并可能被误作最终答复。
这次复现使用虚构记录，没有读取或发布真实聊天，也没有向 Desktop 或模型发送任务。

## 修复行为

每次构建时间线时，一个旧组 key 只能由一个新组继承；新组的备用 key 也需检查
唯一性。拆组、合组和原生重排不会再产生相同身份的兄弟节点。
仍存在的组尽量沿用已有身份；合并后被移除的独立组不承诺保留自己的局部展开状态。

没有正文和提问的助手占位不进入显示分组，也不作为最终答复锚点。真实进度正文、
仅含原生提问的消息、用户引导、轮次与查看图片的边界继续保留。
最终答复锚点要求可见正文，不将仅提问的记录当作最终回复。

## 详情与验收边界

组标题展开只挂载内部摘要；需要完整命令输出或差异时，仍在展开具体条目后，
通过已认证的 `/api/thread/item` 按所属聊天、轮次和条目读取详情。读取失败保留
错误与重试入口；关闭条目或替换其摘要会取消该次读取。没有原生定位信息时，
应显示无法读取详情的原因，不能伪造输出或自动重复命令。

组内首次最多挂载末尾 60 条，点击“显示更早的记录”后每次增加 120 条。
此限制与原生历史分页、详情按需读取继续独立；本次没有改成一次加载完整历史。

浏览器验证覆盖真实 React 交互及合成详情成功响应，不证明真实 Desktop 的每种
工具输出、详情失败恢复、断网、超长输出或所有活动类型均已重新验收。
Chrome 模拟手机尺寸和触摸不等于真实 iPhone Safari、主屏幕应用、移动网络或
已登录 macOS 的现场验收。正式发布、部署和公共静态资源状态另以对应发布及部署
记录为准。
